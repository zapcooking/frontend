# Replace NIP-78 account backup with Lazarus data recovery

## What changes

**Remove** the NIP-78 account-backup feature (settings "Nostr Backup" accordion + ProfileEditModal backup features + `nostrBackup.ts` + `profileBackup.ts`). **Replace** with a Lazarus (spec 0.5.0-draft) "Data Recovery" screen in Settings and a recovery entry on the profile page — relay-history scanning, clobber-detection ranking, delta review, explicit-click restore through the app's own signer.

**Kept untouched** (not account backup): wallet NWC/Spark NIP-78 backups (WalletPanel + login auto-restore), and all other 30078 app-data codecs — timerSettings, autoZapSettings, nourish, cheffys-table, spark, grocery/pantry/planner services, Google Drive key backup.

## Decisions taken (my call, veto if wrong)

1. **Kinds: Tier 1 + 2** — follows (3), mutes (10000), profile (0), bookmarks (10003), NIP-4e keys (10044 with intent flow). Covers everything the old backup covered plus bookmarks; Tier 3 relay-list kinds wait. Registry still carries all 8 kinds (single source of truth); the UI renders Tier 1–2.
2. **Retire the pre-Lazarus Mutable recovery** (`followRecovery.ts`, `FollowListRecoveryModal.svelte`): delete both; the profile page's "Restore Follow List" repoints at the Lazarus UI. Lazarus fixes its three limits (NIP-07-only signing, kind-3-only, no delta rule) and one recovery system beats two that drift.
3. **Vendor the core, don't rewrite from spec**: the framework-free Lazarus core already exists in `dmnyc/jank` branch `feat/lazarus-data-recovery` (`src/services/lazarus/{registry,private-items,recovery}.ts`, ~1000 lines + ~930 lines of spec tests; nothing is on npm). Port it rather than reimplement — spec conformance vectors come with it.

### Phase A — vendor the core → `src/lib/lazarus/`
- **`registry.ts`** — port as-is (imports only nostr-tools `Event` type; we have nostr-tools 2.25). Kind profiles: tier, ranking profile, meaningful-empty flag, required warnings, item counting.
- **`private-items.ts`** — port; **replace its one zod import** (zod isn't a dependency here) with a hand-rolled JSON guard. NIP-44/NIP-04 payload sizing for estimated private-item counts.
- **`recovery.ts`** — port the pure functions (clobber-detection ranking with episodes/settling, delta by tag type+value, profile field diffs, `buildLazarusRecoveryDraft` with `created_at = max(now, current+1)`, candidate grouping/sorting, NIP-46 65,535-byte cap check, paging via `until` cursors). Implement its injection seam `LazarusRelaySource` zap-side: nostr-tools `SimplePool` per-relay `querySync` + 6s timeout + dedupe-by-id + found-on attribution — the pattern already proven in `followRecovery.ts:85-105`. Relay catalog: user's kind-10002 read+write relays (existing `relayListCache.ts`) + pool relays + the spec's 6 archival relays.
- **`lazarusPublish.ts`** (new, zap-side) — draft → `NDKEvent` → `await ev.sign()` (works for NIP-07, nsec, and NIP-46 — fixing the old NIP-07-only recovery), pre-sign re-check of current version, publish to write relays + best-effort to answering relays, author-pubkey guard, then refresh the app's local copy per kind (`followListCache.resetCache()`, `muteListStore.invalidate()`, `profileCacheManager.invalidateProfile()`).
- **Tests** — port the ~70-case recovery spec + private-items vectors to vitest (`src/lib/lazarus/*.test.ts`). This is the spec's Tier-1 conformance requirement.

### Phase B — UI

Built on the existing stage-machine + Modal + CSS-var conventions.

## Notes
- Spec is 0.5.0-draft: vendored files carry a provenance comment naming repo/branch/spec version, so drift is traceable when 1.0 lands.
- Private items: exact counts when a local nsec session can decrypt (existing `encryptionService`), estimated from payload sizing for NIP-07/NIP-46 — both conformant tiers.
- No NIP-78 account-backup data migration: old backup events are left on relays unread (they were encrypted 30078s; harmless), and Lazarus reads the *canonical* kinds, which the backups never touched.
