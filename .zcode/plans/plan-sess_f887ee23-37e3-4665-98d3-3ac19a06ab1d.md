# Replace Giphy with nostr.build GIFs in zapcooking

**Reference implementation:** sidecar `composer-core.js:2260–2628` + `test/gif-picker.test.js`. The gifs.nostr.build API has **no trending endpoint** — only `GET /api/v1/search` and `GET /api/v1/suggest` — so the "open on trending" behavior becomes sidecar's "open on topic chips". Every nostr.build result is already hosted on `image.nostr.build`, so (like sidecar) we **drop the download-and-rehost step** — picking a GIF just attaches its URL.

**Auth (my recommendation, applied since the question timed out):** the zap cooking `gnb_` key lives **server-side** in a SvelteKit proxy route. The nostr.build guide explicitly says web apps must never send `Authorization` from browser code (that's for native apps; sidecar is an extension, hence its hardcoded key). A proxy keeps the key out of the bundle, works on every deploy domain (zap.cooking, Vercel previews), and matches zapcooking's existing proxy pattern (`api/youtube-oembed`, `api/link-preview`). If you'd rather ship the key client-side sidecar-style, that's a small later change.

## Steps

### 1. `src/lib/gifSearch.ts` — pure API module (new)
Port sidecar's logic as testable pure functions + types:
- `gifSearchUrl(q, offset)` / `gifSuggestUrl(q)` — build **proxy** URLs (`/api/gif-search?...`) carrying the upstream params verbatim: `q` (trimmed, ≤500 chars), `limit=24`, `offset`, `safe=1`; suggest: `limit=6`, `safe=1`.
- Constants: `GIF_PAGE_SIZE=24`, `GIF_LAST_OFFSET=199` (API rejects offsets past 199), `GIF_QUERY_MAX=500`, `GIF_SUGGEST_LIMIT=6`, `GIF_TOPICS = ['gm','gn','pv','zap','bitcoin','coffee','lfg','wow']`, `gifTopicsFor(now)` (gm first 04:00–17:59 local, gn otherwise).
- `gifFromItem(item)` — strict validation since the URL gets published: https `url`, format must be `gif|webp` (mp4 dropped), positive width/height, preview from `previews.w240` (fallback `medium`), first https of `[animated, still]`. Returns `{ url, preview, width, height, title }` or null.
- `parseGifPage(body)` — `{ items, offset, count }` → `{ gifs, next }`, `next` only while `next < count && next <= 199`.
- `parseGifSuggestions(body)` — trim/dedupe/cap 6 from `terms[].term`.
- `gifErrorMessage(status)` — 401/403 → "GIF search isn't available right now."; 429 → "Too many searches. Try again in a minute."; else → "Couldn't load GIFs…".

### 2. `src/lib/gifSearch.test.ts` (new)
Port sidecar's suite to vitest (zapcooking's pure-function lib test pattern): URL/param shapes, `gifFromItem` accept/reject matrix (http:, mp4, zero dims, missing preview, preview fallback chain), page/offset math + 199 cap, suggest dedupe/cap, error mapping, `gifTopicsFor` clock ordering.

### 3. Proxy routes (new)
- `src/routes/api/gif-search/+server.ts` and `src/routes/api/gif-suggest/+server.ts` — GET handlers following the `youtube-oembed` pattern: validate `q` (required, ≤500), rebuild the upstream URL against `https://gifs.nostr.build/api/v1` with `limit/offset/safe` forwarded, `Authorization: Bearer ${key}` + `Accept: application/json`, AbortController timeout, pass through the JSON body and upstream status (so the client's 429/401 mapping still works). Missing/unset key → 503 so the picker says "unavailable".
- Key via `$env/dynamic/private`: **`GIFS_NOSTR_BUILD_API_KEY`** (matches existing `BRANTA_API_KEY`/`STRIPE_*` naming). Add to `.env.example`.
- No CSP change needed (`connect-src https:` wildcard, svelte.config.js:68).

### 4. Rewrite `src/components/GifPicker.svelte` internals (keep the Modal shell and Svelte-4 syntax)
- **Attribution** (registration promise): "GIFs from **nostr.build**" link (`https://nostr.build`, `target=_blank rel="noopener noreferrer"`) always visible in the picker — replaces the "Powered by GIPHY" badge.
- Search input (maxLength 500, keep autofocus-on-open); **350ms debounce** (sidecar parity); Enter searches immediately; Escape closes.
- **Chips row**: topics while empty (`gifTopicsFor`), `/suggest` terms while typing (failures silently ignored).
- **Masonry grid** replacing the 1:1 cropped grid: 2–5 flex columns (width/170), shortest-column packing, each `<img loading="lazy" decoding="async" referrerPolicy="no-referrer">` gets `aspect-ratio` from width/height before load (no scroll jumps).
- **Infinite scroll**: load next page within 160px of bottom; dedupe by URL across pages.
- **Abort handling**: AbortController per request; abort on new search and on close; reopen re-runs the pending search if it was cut off.
- States: loading spinner (existing), idle "Search or pick a topic.", empty "No GIFs found for “{query}”.", error line via `gifErrorMessage`.
- **Pick = instant attach**: `dispatch('select', { url: gif.url, title: gif.title })` — no blob fetch, no upload, no uploading overlay.
- Removed: Giphy attribution, `VITE_GIPHY_API_KEY`, the no-key fake tiles, `selectGif` rehost logic.

### 5. Composer wiring — one-line change each
- `PostComposer.svelte:~1546` and `ReplyComposer.svelte:~1097`: `on:select` handler seeds alt like sidecar: `media = [...media, { url: e.detail.url, isVideo: false, alt: e.detail.title || '' }]` — published GIFs then get a NIP-92 imeta tag through the existing `imetaTagsForMedia`.
- Keeping zapcooking's existing poll/media coexistence (sidecar forces exclusivity — existing zapcooking behavior, out of scope).

### 6. Removals
- `uploadGif` + `MAX_GIF_SIZE` from `src/lib/mediaUpload.ts` (GifPicker was the only consumer — verified by grep).

### 7. Privacy page
- `src/routes/privacy/+page.svelte:164`: replace the `api.giphy.com` disclosure — search terms now go to gifs.nostr.build (via our server, which holds only the API key), previews load from image.nostr.build, and nothing is sent until the picker is opened (mirrors sidecar PRIVACY.md:94–99).

### 8. Verify
- `npm test`, `npm run check`, `npm run lint`; then a GUI pass (dev server + browser automation): open picker → chips render → tap chip → search → infinite scroll → pick → GIF lands in composer media strip with title as alt → publish renders in preview. Requires `GIFS_NOSTR_BUILD_API_KEY` in your local `.env` (please add the zap cooking key there — I'll flag it if missing).

**No changes needed downstream:** `.webp` is already in `IMAGE_EXTENSIONS` and `image.nostr.build` is in both `EXTENSIONLESS_IMAGE_HOSTS` and the optimizer's native-rendition set, so feed rendering/lightbox/optimization just work. `docs/security/vulnerability-scan-2026-08.md` SEC-16 becomes moot (historical doc, leaving it). **You'll need to:** add `GIFS_NOSTR_BUILD_API_KEY` to Vercel (fork) and Cloudflare (upstream) env dashboards at deploy time, and can drop the now-unused `VITE_GIPHY_API_KEY` from your `.env`.
